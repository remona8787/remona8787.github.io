  - 스프레드시트가 수식으로 실행할 수 있는 텍스트는 막습니다.

### 회원 등급 연구 데이터 — 구현 완료·검증 필요, 외부 설정 필요

## 5. 배포

### 배포 구조 — 검증 완료

- `source` 브랜치에 푸시하면 다음 순서로 진행됩니다.
  1. 커밋 메시지에 `[collect]`가 있으면 수집합니다.
  2. 배포합니다.
  3. verify-live가 실제 사이트를 열어 확인합니다.
- 이번 세션에서 RC16–RC20 다섯 번을 배포했고, 다섯 번 모두 verify-live가 success였습니다(14개 화면, 콘솔 오류 0, 깨진 이미지 0).
- 매시간 재배포는 예약 작업으로 하고 있습니다. 녹색으로 확인된 변경만 합칩니다.

### 정기 자동 실행 — 일부 확인

- 6시간마다 도는 예약 실행은 2026-10-20부터 23회 있었습니다. 그중 20회를 확인했고 모두 success였습니다.
- GitHub의 예약 실행은 정해진 시각보다 늦게 시작되기도 합니다(예: 12:17 예약이 13:08에 시작).
- 성공 기록은 '실행이 끝까지 돌았다'는 뜻입니다. 사람 검수 없이 수집된 데이터의 품질까지 확인됐다는 뜻은 아닙니다. 실제로 이번 작업 중에도 자동 수집 결과에서 비프로젝트가 공개된 일이 두 번 있었고(10-26 오전 6건, 21:34 1건), 사람이 찾아 원인을 고쳤습니다.

### 비밀값

- API 키는 GitHub Actions Secrets에만 둡니다.
- 프런트엔드와 공개 JSON에는 publishable(anon) 키만 둡니다. 이번에 `scripts/check.mjs`에 검사를 추가했습니다. 브라우저가 받는 모든 파일(`dist/`, 관리자 화면, 클라이언트 코드)을 검사해 Supabase 비밀키(`sb_secret_…`), service_role JWT, 개인키가 있으면 실패합니다. 심어 둔 비밀키와 service_role JWT는 잡고, anon JWT는 통과시키는 것을 확인했습니다.
- 관리자 데이터와 개인정보는 공개 사이트에 배포하지 않습니다(`data` 브랜치에만 있음).

### 개발 브랜치

- `ymin02/medieval_era_project`의 `claude/light-architecture-launch-ohxxxi`로의 푸시는 계속 403으로 거부됩니다. 해당 조직에 Claude GitHub App이 설치되지 않았기 때문입니다.
