# 「빛의 건축」 수익화·호스팅·운영 조건 검토 (v0.19 기준)

작성: 2026-10-26. 이 문서는 사실 확인 결과와 운영 판단을 나눠서 적습니다. 확인 수준은 각 항목에 다음처럼 표시합니다.

- **[공식]** 제공사·기관의 공식 문서로 확인한 내용
- **[2차]** 블로그·비교 사이트 등 2차 자료로만 확인한 내용. 실제 적용 전에 공식 문서를 다시 확인해야 합니다.
- **[미확인]** 확인하지 못한 내용

방문자 수, 클릭률, 광고 단가, 예상 매출은 아직 측정한 값이 없어서 이 문서에 숫자로 적지 않습니다. 수익 항목은 변수로 된 시나리오 공식만 제시합니다.

## 1. 원칙

1. 전문성과 신뢰가 광고보다 우선합니다. 광고와 협찬은 항상 "광고" 또는 "후원"으로 표시합니다. 스폰서는 프로젝트 평가, 검색 순위, 지도 표시, 대표 이미지 선정에 영향을 줄 수 없습니다.
2. 공개 원천 데이터에 대해 독점권을 주장하지 않습니다. Wikidata(CC0), Commons(각 파일 라이선스), 공공누리 자료가 여기에 해당합니다. 유료 상품은 플랫폼이 직접 더한 가치에만 가격을 붙입니다. 검수, 분류, 주석, 비교 분석, 맞춤 추출, 보고서가 그 예입니다.
3. 상업적 이용 조건이 붙은 콘텐츠는 상업 기능과 분리합니다(5절).
4. 결제는 결제대행사(PG)의 결제창만 씁니다. 카드 정보는 저장하지도 경유시키지도 않습니다.
5. 외부 계정 생성, 광고 신청, 계약, 결제 활성화는 소유자가 직접 결정합니다. 이 저장소에는 준비물만 둡니다(8절).

**판단**

- **지금(1단계):** 공개 아카이브는 GitHub Pages에 그대로 둡니다. 비상업 연구 아카이브이고 거래 기능이 없으므로 제한에 걸리지 않습니다.
- **로그인·연구 데이터:** 회원 인증과 다운로드 권한 확인은 Pages가 아니라 Supabase에서 처리합니다. 인증, Row Level Security, Edge Function, 비공개 Storage를 씁니다. Pages에는 비밀값을 두지 않습니다.
- **광고·후원 시험(2단계) 전:** 광고나 유료 협찬이 사이트의 주된 목적이 아니라도 상업 활동이 시작되는 시점입니다. 그 전에 정적 사이트를 상업 이용이 허용되는 호스팅으로 옮길지 소유자가 결정합니다. 후보는 Cloudflare Pages(약관 확인 후), 유료 정적 호스팅, 자체 도메인입니다. 사이트가 정적 파일 묶음이라 이전 비용은 작습니다. 이전이 필요해지는 시점은 `archive.yml`의 deploy 단계를 바꾸는 때입니다.
- **결제(3단계):** 결제와 구독은 PG 결제창과 서버 측 확인(웹훅)으로만 처리합니다. Pages에서는 결제를 받지 않습니다.

## 3. 수익 모델 비교

| 모델 | 무엇을 파는가 | 플랫폼 적합도 | 선행 조건 | 위험 | 단계 |
|---|---|---|---|---|---|
| A. 전문 스폰서십·협찬 | 공식 후원기관 표시, 스폰서 섹션, 표시된 협찬 기사, 업계 행사 소개 | 높음. 미디어파사드 제작사, LED·조명 기업, 미디어아트 운영사, 문화기관과 주제가 맞습니다. | 실측 방문 통계, 후원 정책, 표시 규칙, 문의 창구, (상업 호스팅) | 편집 독립성 훼손 우려 → 정책으로 차단 | 2 |
| B. 일반 디스플레이 광고(AdSense 등) | 광고 노출 | 낮음~중간. 전문성을 해치기 쉽고, 트래픽이 적으면 수익이 작습니다. | 자격 요건 충족, 동의 관리(해외 이용자), 상업 호스팅, 성능 예산 | 가독성·속도 저하, 저품질 광고 | 2(제한적 시험) |
| C. 연구용 프리미엄 | 검수·주석 데이터 패키지, 비교 도구, 통계 대시보드, 맞춤 추출, 보고서 | 높음. 플랫폼이 더한 가치에 해당합니다. | 회원 인증, 버전 관리된 데이터셋, 이용약관, 결제 | 원천 데이터 재포장 논란 → 부가가치 범위만 판매 | 3 |
| D. B2B·기관 서비스 | 지자체 미디어파사드 현황 조사, 사례 DB 구축, 비교 분석, 시장 보고서 | 높음. 계약 단위 수익입니다. | 레퍼런스(공개 아카이브 품질), 견적·계약 체계 | 수요 검증 전 과투자 | 2~3 |
| E. 자체 콘텐츠 | 도서 소개·판매 연계, 강의·워크숍, 연구 리포트 | 중간~높음. 운영자의 출판·교육 활동과 연결됩니다. | 콘텐츠 기획, 판매 채널(외부 서점·플랫폼) | 운영 부담 | 2~3 |

**추천 순서:** 사이트 품질과 실측 지표를 먼저 확보한 다음, D(기관 협력) → A(전문 후원) → C(연구 프리미엄) → E 순으로 진행합니다. B(일반 광고)는 효과를 측정할 수 있는 제한적 시험으로만 둡니다. 이 분야는 사용자층이 작고 전문적이어서, 노출량에 비례하는 광고보다 신뢰를 바탕으로 한 계약형 수익이 맞습니다.

### 시나리오 공식 (측정값으로 채움, 지금은 비어 있음)

- 광고: 월 수익 = 월 페이지뷰 × (광고 노출 비율) × RPM / 1000
- 후원: 월 수익 = 후원사 수 × 월 후원 단가
- 연구 프리미엄: 월 수익 = 활성 회원 × 유료 전환율 × 월 요금 − PG 수수료
- B2B: 연 수익 = 계약 건수 × 평균 계약 금액

각 변수는 실제 측정값을 넣습니다. 측정 경로는 관리자 대시보드의 방문·회원·다운로드 통계입니다. 측정 기간과 표본 크기를 함께 적습니다.

## 5. 콘텐츠 권리와 상업 이용

- **공공누리:** 제1유형은 출처표시 시 상업 이용과 변경이 가능합니다. 제2유형은 상업 이용이 금지됩니다. 제3유형은 변경이 금지됩니다. 제4유형은 상업 이용과 변경이 모두 금지됩니다. 어떤 유형이든 출처 표시가 필요합니다. [공식: 문화체육관광부·지자체 안내]
- **현재 파이프라인의 공공누리 처리:** 한국관광공사 이미지는 KOGL 제1·3유형만 받습니다(제3유형은 `no_derivatives`, 자르기 없이 원본 비율로 표시). Flickr·Openverse에서는 NC(비영리) 라이선스를 받지 않습니다.
- **상업 기능을 켜기 전에 할 일:** 광고나 후원 슬롯을 켜기 전에, 해당 페이지의 이미지가 상업 이용이 가능한 조건인지 다시 검사합니다. 기준은 비상업 서비스보다 엄격하게 둡니다. 검사 대상은 공공누리 2·4유형, CC BY-NC, 권리 미확인 이미지입니다. 해당 이미지가 있는 페이지에는 광고를 넣지 않거나 그 이미지를 표시하지 않습니다. 이 규칙은 광고 슬롯 구성에 `commercial_safe` 조건으로 넣습니다.
- **공개 데이터셋 다운로드:** 공개 데이터셋은 각 출처의 라이선스를 그대로 표시합니다. 회원용 패키지에 붙는 조건은 플랫폼이 직접 작성한 부분(분류·주석·해설)에만 적용합니다.

## 7. 구현 상태

- **스폰서·광고 슬롯 컴포넌트:** 설정 파일(`data/sponsors.json`)이 없으면 아무것도 표시하지 않습니다. 표시할 때는 "후원" 또는 "광고" 라벨을 붙이고, 갤러리 안에는 넣지 않으며, 페이지당 1개까지 본문 아래에만 둡니다. UI 트랙에서 구현 중입니다.
- **파트너·후원 문의 페이지:** 정적 페이지와 이메일 문의만 둡니다. 결제 기능은 없습니다.
- **유료 기능:** 화면에 "결제 가능"처럼 보이는 요소를 두지 않습니다. 준비되지 않은 기능은 "준비 중"으로 표시합니다.
- **회원 연구 데이터:** 서버 측 설계와 SQL은 `docs/RESEARCH_DATA.md`에 있습니다. Supabase 프로젝트가 연결되기 전까지는 "준비 중"으로 표시됩니다.

## 8. 소유자 결정·승인이 필요한 일 (준비와 실제 활성화 구분)

| 일 | 저장소에 준비된 것 | 소유자가 할 일 |
|---|---|---|
| 회원 인증 | SQL·RLS·Edge Function 코드, 설정 방법 | Supabase 프로젝트 생성, 공개 키(anon/publishable)를 `config.js`에, 비밀키는 Supabase 함수 환경변수에만 설정 |
| 광고(AdSense 등) | 슬롯 컴포넌트(기본 꺼짐), 성능 예산 | 계정 신청, 심사, 동의 관리 도구 선택, 상업 호스팅 결정 |
| 후원 | 슬롯, 표시 규칙, 문의 페이지 | 후원 정책 확정, 계약, `sponsors.json` 작성 |
| 결제·구독 | 설계만 있음(PG 결제창, 서버 웹훅 확인) | 사업자등록, 통신판매업 신고, PG 가입·심사 |
| 호스팅 이전 | 정적 빌드 그대로 이전 가능 | 대상 호스팅 선택, 도메인 구입·연결 |
