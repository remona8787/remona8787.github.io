# 국내 공공데이터 연동 현황 (v0.19)

작성: 2026-10-26.

이 문서는 실제 코드와 실행 기록(`data` 브랜치의 `review/`, `admin-data/report.json`)으로 확인한 사실만 적습니다.

**확인 출처 표시**

| 표시 | 의미 |
|---|---|
| [공식] | 제공 기관 페이지나 공식 문서에서 확인 |
| [2차] | 검색 결과의 2차 자료에서 확인 |
| [미확인] | 직접 확인하지 못함 |

이 컨테이너는 data.go.kr과 data.seoul.go.kr에 접속할 수 없습니다. 그래서 실제 응답 형식은 GitHub Actions의 수집 실행에서 확인합니다.

**상태 값**

| 값 | 뜻 |
|---|---|
| 코드만 | 코드는 있지만 실제로 연결된 적이 없음 |
| 키 필요 | 키가 없어서 실행할 때마다 건너뜀 |
| 연결 성공 | 실제 응답을 받음 |
| 수집·비공개 | 수집했지만 공개 기준(관련성·검수)을 통과하지 못함 |
| 공개 반영 | 공개 사이트에 반영됨 |
| 오류 | 연결이 실패함 |

## 2. 우선 연계 대상 (확인 결과)

### 2-1. 한국관광공사 국문 관광정보 KorService2 (data.go.kr 15101578)

- **제공:** 한국관광공사. 기본 주소는 `https://apis.data.go.kr/B551011/KorService2`입니다. [공식, 파이프라인 구현 시 확인]
- **사용하는 오퍼레이션:**

  | 오퍼레이션 | 용도 |
  |---|---|
  | `searchKeyword2` | 콘텐츠 유형 12 관광지, 14 문화시설, 15 축제·행사를 미디어아트 관련 국문 검색어로 검색 |
  | `detailCommon2` | 개요, 홈페이지 |
  | `detailImage2` | 이미지와 저작권 구분 `cpyrhtDivCd` |

- **이미지 처리:**
  - 공공누리 제1유형(출처표시)과 제3유형(출처표시·변경금지)만 받습니다. 제3유형은 자르지 않고 원본 비율로 표시합니다(`no_derivatives`).
  - 제2·4유형은 상업 이용이 금지되므로 받지 않습니다.
- **호출 제한:** 초당 2회. 한 번 실행할 때 새 개요 조회는 120건, 이미지 조회는 300건까지입니다.
- **키 발급:** data.go.kr에서 "한국관광공사_국문 관광정보 서비스_GW"와 "한국관광공사_관광사진 정보_GW"를 각각 활용신청해야 합니다.
- **관련성 판단:** 제목이나 개요에 미디어파사드·미디어아트·프로젝션 매핑·빛축제 등 검색어가 있고 분류기도 동의해야 후보가 됩니다. 판단 기록은 모두 `review/tourapi.json`에 남습니다.
- **상태:** 코드 완료, 키 필요.

### 2-2. 서울시 문화행사 정보 (서울 열린데이터광장)

- **같은 제목의 데이터셋이 둘 있습니다.** 둘의 관계는 [미확인]입니다.

  | 데이터셋 | 공개일 | 내용 |

  둘 다 매일 1회 갱신됩니다. [2차]
- **OA-15486 상세:**
  - 이용허락: 공공누리 제1유형(출처표시, 상업 이용·변경 가능). [2차]
  - 주요 필드: 자치구, 공연/행사명, 장소, 날짜, 기관명, 이용대상, 이용요금, 출연자, 프로그램, 홈페이지, 위경도, 시작일, 종료일, 무료 여부. [2차]
  - 호출 형식: `http://openapi.seoul.go.kr:8088/{인증키}/json/culturalEventInfo/{시작}/{끝}/` [2차, 서드파티 예제]
  - 이 저장소의 Supabase 함수도 같은 형식을 씁니다.
- **OA-23041:** API 서비스명은 [미확인]입니다. 첫 실행에서 서비스명과 필드명을 확인합니다.
- **주의:** 주소가 http(평문)이고 포트가 8088입니다.
  - 키가 주소 경로에 들어가므로 다른 호스트로 리다이렉트되면 따라가지 않습니다.
  - GitHub Actions에서 접속 가능한지 첫 실행에서 확인합니다.
- **관련성 판단:** 행사명·프로그램·장소에 미디어아트·미디어파사드·프로젝션·빛·라이트 등의 단어가 없으면 프로젝트로 등록하지 않습니다.
- **연결 방식:** 행사는 장소(Place)에 연결된 행사(Event) 레코드로 만들고, 같은 장소를 중복으로 만들지 않습니다.
- **키:** `SEOUL_OPEN_DATA_KEY`(Supabase 함수와 같은 이름)를 GitHub Secret으로 등록합니다.
- **상태:** 정적 파이프라인 연결은 미구현(수집 트랙에서 구현 예정), 키 필요.

### 2-4. 문화공공데이터광장 (culture.go.kr)

- **배경:** 문화체육관광부와 한국문화정보원이 운영하는 문화 데이터 개방 창구입니다. 2016년 발표 기준으로 오픈API 240여 종을 제공했습니다. [공식 보도자료, 현재 구성은 미확인]
- **미확인 사항:** 전시·공연 API의 현재 명세, 키 발급 방법, 이용허락 범위는 [미확인]입니다.
- **활용 방향:** 미디어아트 전시를 고르고, 상설 미디어파사드인지 일시 전시인지 구분하는 데 씁니다. 일시 전시는 Exhibition 레코드로 만들어 장소에 연결합니다.
- **상태:** 미구현, 명세 확인 필요.

### 2-5. 서울시 실시간 도시데이터 (data.go.kr 15146211, 서울 OA-22714)

- **제공 범위:** 주요 120~121개 장소(출처마다 수가 다름)의 실시간 인구, 교통, 날씨, 문화행사 정보입니다. [2차]
- **호출 방식:** 한 번에 한 장소만 조회합니다. 샘플키로는 '광화문·덕수궁'만 조회할 수 있습니다. 실시간 데이터만 있고 과거 데이터는 쌓이지 않습니다. [2차]
- **이용허락:** 공공누리 제1유형. [2차]
- **판단:** 프로젝트를 발견하는 용도가 아니라, 지원 장소에 있는 프로젝트의 방문 정보(혼잡도 등)를 보여 주는 용도입니다. 실시간 정보라서 정적 사이트에 미리 저장할 수 없습니다. 사용자가 상세페이지를 볼 때 서버 함수로 조회해야 합니다. 우선순위는 낮습니다.
- **상태:** 미구현.

## 3. 통합 처리 흐름 (정적 파이프라인)

수집 → 표준 필드 변환 → 미디어파사드·미디어아트 관련성 평가(검색어 + 분류기, 판단 기록 남김) → 장소·작품·행사 구분 → 중복 식별(이름 + 300m 이내, 제공처 ID, QID) → 공식 출처 교차 확인 → 병합 → 이미지 탐색·검수(동일성 증명이 약한 사진은 승인 대기) → 공개

- 제공처가 오류를 내면 직전의 정상 데이터를 그대로 유지합니다(`kept_previous`).
- 각 레코드에 데이터 기준일과 출처 라이선스를 기록합니다.
