# 연구 데이터 서비스와 회원 인증 (v0.19)

서버 코드는 다음 세 곳에 있습니다.

- `supabase/migrations/20261026000000_research_data.sql`
- `edge-functions/research-download/index.ts`
- `tests/research-sql.test.mjs` — PostgreSQL(PGlite) 테스트

화면은 UI 트랙이 `site-public-cleared/`에서 만듭니다.

**상태: 구현 완료, 검증 필요, 외부 설정 필요.** 운영자의 Supabase 프로젝트가 아직 연결되지 않았습니다. 그래서 공개 사이트에서는 회원 연구 데이터가 "준비 중"으로 표시되고, 로그인과 다운로드 버튼은 동작하지 않는 것처럼 보이지 않도록 감춰져 있습니다. SQL은 PGlite에서만 검증했고, 실제 Supabase에서는 아직 실행해 보지 않았습니다.

## 1. 데이터 등급

| 등급 | 무엇 | 어디에 | 누가 |
|---|---|---|---|
| 공개 | 프로젝트 정보, 공식 출처, 기본 통계, 공개 데이터셋. 각 출처의 라이선스를 그대로 따릅니다(Wikidata CC0, Commons 파일별 라이선스, 공공누리 유형별 조건). | GitHub Pages `/data/`와 연구 데이터 페이지의 CSV·JSON | 누구나, 로그인 없이 |
| 회원 연구 자료 | 플랫폼이 직접 검수·분류·주석한 데이터셋, 버전별 패키지, 데이터 사전 | Supabase 비공개 Storage `research-datasets` | 이메일 인증을 마치고 이용조건에 동의한 회원 |
| 기관·전문 서비스 | 맞춤 분석, 대량 제공, 비교 보고서 | 계약별 전달 | 계약 기관 |

회원 등급으로 나누는 근거는 플랫폼이 직접 더한 작업(검수, 분류, 주석, 해설)입니다. 공개 원천 데이터를 회원 전용으로 만들거나 독점권을 주장하지 않습니다. 공개 저장소와 Pages에는 회원 전용 파일을 올리지 않습니다. 회원용 패키지는 `data` 브랜치나 공개 JSON에 포함되지 않고, 비공개 버킷에만 업로드합니다.

## 2. 수집하는 개인정보

| 항목 | 필수 여부 | 필요한 이유 |
|---|---|---|
| 이메일 | 필수 (Supabase Auth) | 계정 식별, 로그인, 비밀번호 재설정 |
| 비밀번호 또는 외부 인증 | 필수 | 로그인 |
| 이용약관·개인정보 처리방침 동의(버전, 시각) | 필수 | 동의 사실 기록 |
| 표시 이름, 소속기관, 이용자 유형, 연구 분야, 이용 목적, 국가 | 선택 | 이용 목적 통계, 향후 기관 라이선스 확인용(그 기능을 실제로 만들 때 필요성을 다시 검토) |

- 선택 항목을 비워 둬도 다운로드할 수 있습니다. 다운로드 조건은 프로필 행(필수 동의 2개)이 있는 것뿐입니다.
- 다운로드 이력에는 사용자 ID, 데이터셋, 버전, 형식, 성공 여부, 시각만 남습니다. 이 이력은 공개 데이터나 공개 저장소에 포함되지 않습니다.
- 탈퇴(`delete-account`)하면 프로필이 삭제됩니다. 다운로드 이력과 신고는 사람을 알 수 없게 사용자 ID만 지운 상태로 남아, 집계 수치는 유지됩니다.
- 오류 신고에 적은 이메일은 신고 처리 상태가 바뀌는 순간 데이터베이스 트리거가 지웁니다.
- 회원 기능을 켜면 처리방침에 다음을 함께 적어야 합니다(`docs/BUSINESS.md` 6절).
  - Supabase: 처리 위탁과 국외 이전에 해당합니다.
  - 보유 기간: 탈퇴 시까지입니다. 다운로드 이력은 사람을 알 수 없게 바꾼 뒤 통계로 보관합니다.

## 3. 다운로드 흐름

1. 연구 데이터 페이지에서 데이터셋, 버전, 형식을 고릅니다. 데이터셋 목록, 버전, 라이선스, 인용문, 체크섬은 공개되어 로그인 없이 볼 수 있습니다.
2. 로그인하지 않았으면 로그인·회원가입 안내가 나옵니다. 이메일 인증이 필요합니다.
3. 처음이면 필수 동의와 선택 정보를 받는 프로필 화면이 나옵니다.
4. 브라우저가 `research-download` 함수에 사용자 토큰을 보냅니다.
5. 함수의 처리 순서는 다음과 같습니다.
   - 토큰으로 사용자를 확인합니다.
   - 이메일 인증 여부를 확인합니다.
   - 시간당 다운로드가 30회를 넘으면 거절합니다.
   - `research_download_check`(서비스 역할 전용)로 회원 등급 데이터셋인지, 버전·형식·프로필이 맞는지 확인합니다.
   - 통과하면 비공개 버킷의 5분짜리 서명 링크를 발급합니다.
   - 성공이든 실패든 이력에 기록합니다.
6. 응답에는 링크와 함께 라이선스, 인용문, 데이터 기준일, 레코드 수, SHA-256이 들어 있습니다.

## 4. 접근 제어 (RLS, 테스트로 확인한 내용)

- `research_profiles`: 본인 행만 조회·생성·수정·삭제할 수 있고, user_id는 바꿀 수 없습니다. 비회원은 접근할 수 없습니다.
- `research_datasets`, `research_dataset_versions`: 활성 항목만 누구나 조회할 수 있고, 쓰기는 서비스 역할만 가능합니다.
- `research_downloads`: 회원은 본인 행만 조회하고, 쓰기는 서비스 역할(함수)만 가능합니다.
- `research_download_check`: 비회원과 회원은 실행할 수 없고, 서비스 역할만 실행합니다.
- `content_reports`(이미지·정보 오류 신고):
  - 누구나 제출할 수 있습니다. 다만 처리 상태를 미리 정하거나 남의 이름으로 제출할 수는 없습니다.
  - 조회와 처리는 admin과 editor만 할 수 있고, 신고 원문은 수정할 수 없습니다.
  - 신고가 데이터를 자동으로 바꾸지 않습니다. 반영은 편집 결정(`editorial/decisions`)으로만 합니다.
- `research_admin_stats`: admin만 실행합니다. 결과는 회원 수, 다운로드 수, 데이터셋별 이용, 이용자 유형 분포, 오류, 미처리 신고 같은 집계값뿐이고 개인 단위 행은 없습니다.
- `research-datasets` 버킷은 비공개이고, 회원 역할을 위한 Storage 정책이 없습니다.

## 5. 운영자 설정 (외부 설정 필요)

1. Supabase 프로젝트를 서울 리전(ap-northeast-2)으로 만들고(개인정보 처리방침 3절의 저장 위치와 일치해야 합니다) 다음 마이그레이션을 순서대로 실행합니다.
   - `supabase/migrations/20261018000000_media_facade_archive.sql`
   - `supabase/migrations/20261026000000_research_data.sql`
2. Auth 설정에서 이메일 인증을 켜고, Site URL(https://remona8787.github.io)과 Redirect URL을 등록합니다.
3. 함수를 배포합니다: `supabase functions deploy research-download`, `delete-account`. 함수 환경변수 `ALLOWED_ORIGINS=https://remona8787.github.io`를 설정합니다. 비밀키(`SUPABASE_SECRET_KEYS` 또는 `SUPABASE_SERVICE_ROLE_KEY`)는 Supabase 함수 환경에만 두고, 브라우저 설정이나 이 저장소에는 넣지 않습니다.
4. 사이트 설정 `config.js`에 공개 URL과 publishable(anon) 키만 넣습니다.
5. 운영자 계정을 `app_admins`에 `admin`으로 등록합니다.
6. 회원용 데이터셋을 만들면 다음 순서로 올립니다.
   - 비공개 버킷에 `<dataset>/<version>/<dataset>-<version>.<format>` 경로로 업로드합니다.
   - `research_datasets`와 `research_dataset_versions`에 행을 추가합니다. 버전, 기준일, 레코드 수, 형식, SHA-256, 변경 내역, 인용문을 함께 넣습니다.

## 6. 데이터셋 구성 (회원·공개 공통)

각 버전은 다음 파일을 함께 냅니다.

- 데이터: CSV, JSON, GeoJSON(좌표가 있는 레코드), 선택적으로 XLSX
- `datapackage.json`: 데이터셋 ID, 버전, 생성일, 데이터 기준일, 총 건수, 국가·지역, 필드 정의, 출처, 검증 상태, 결측치 설명, 이용 조건, 권장 인용문
- `SOURCES.csv`: 레코드별 출처와 라이선스
- `CITATION.txt`
- `CHANGELOG.md`: 이전 버전과의 차이

같은 버전은 내용이 바뀌지 않습니다(SHA-256으로 확인할 수 있습니다). 내용이 바뀌면 새 버전을 냅니다.
