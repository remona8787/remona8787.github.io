# v0.13.3 — 사진 연결 및 6시간 갱신 준비

2026-10-12. 정식 출시 완료가 아님.

## 구현 및 검증
- 문화역서울284 / 서울시립미술관 서소문본관: Commons 원본 설명·저작자·라이선스를 확인한 과거 외관 사진 2곳 연결. 홈, 카드, 상세 갤러리에 사용. 촬영일과 현재 행사 사진이 아니라는 설명 포함.
- 사진은 현재 Commons 직접 연결이다. Supabase Storage 캐시 확보로 표기하지 않는다. 썸네일 실패 시 원본 한 번 시도, 둘 다 실패하면 안내 표시.
- DDP 검토 사진의 NoFoP 경고를 발견해 공개 사진 목록에서 제외. Commons 서버 조회에서 카테고리와 추가 권리 제한도 검사한다. 라이선스 문자열만으로 건축물·작품까지 사용 가능하다고 판단하지 않는다.
- 새 Wikimedia thumb.wikimedia.org 호스트 허용. HTTPS·정확한 호스트·MIME·바이너리 서명·최대 15MiB·시간 제한 유지.
- 정보 후보 / 사진 후보 / 권리 재확인 예약을 6시간 설정으로 통합. 구 일간·주간 SQL 진입점은 새 설치 스크립트를 안내한다.
- 사진 후보가 항상 처음 10곳에 머무르지 않도록 순환 처리. 권리 검증 TTL과 이미지 CDN 캐시 TTL 6시간.
- 서버 연결 후 사진만 바뀌어도 열린 화면이 5분 간격 및 탭 복귀 때 카탈로그를 다시 조회한다. 계정 기록 Realtime과 외부 수집은 별개다.
- 서버에서 사진이 제거되면 클라이언트 기본 사진을 부활시키지 않는다.
- 자동테스트 90개 통과. build/check 통과. 테스트 결과는 VERIFICATION_v0.13.3.txt.

## 직접 확인한 운영 상태
- Supabase read-only 조회: media_assets 0개, visit_photos 없음, app_admins 없음.
- Commons 설명 페이지 및 이미지 링크는 검색 서비스에서 조회 가능.
- 실행 컨테이너의 Commons API/이미지 다운로드는 HTTP403. 사진 파일을 내려받거나 Storage 캐시 업로드 성공으로 보고할 수 없다.
- 브라우저 렌더링/이미지 decode/모바일 E2E 미검증: managed Sites에서 control-browser 도구 미제공. Sites 지침에 따라 대체 브라우저 설치·서버 우회를 하지 않음.
- 로그인·개인 사진 업로드·2사용자 RLS·기기간 동기화는 아직 실환경 미검증. 공개 config는 미연결 상태 유지.

## 준비된 실행물 — 미실행
1. complete-backend.sql: 앞선 사용자의 PC 작업 보류를 존중해 적용하지 않음.
2. Edge Functions 배포 및 MEDIA_CRON_SECRET / MEDIA_ADMIN_SECRET 서버 설정.
3. install-six-hour-sync.sql: Vault 값 사전 확인 후 세 Cron 등록. UTC 기준이며 한국 00/06/12/18시대 실행. 기존 aol 작업만 제거. SQL은 운영 DB에서 아직 실행하지 않음.
4. scripts/import-reviewed-media.mjs: 환경변수로만 서버 인증 전달, 사진 메타데이터 재검사 후 Storage 캐시 요청. 현재 미실행.
5. DB·Storage 검증 후 공개 config 활성화, qa/ux.spec.mjs 실제 브라우저 실행.

예약 1회당 도시 3개, 사진 후보 장소 10곳, 권리 100개로 제한. 6시간마다 작업을 호출하는 설정이며 **전체 49곳/전 세계의 정보·사진이 매 6시간 모두 갱신된다는 보장은 아님**. 소스 변경 빈도·속도 제한·작업 시간에 따라 처리량을 검증하고 배치를 늘려야 한다. Cron 등록 성공만으로 수집 성공이라 하지 않는다. cron.job_run_details와 ingestion_jobs / sync_runs / media_sync_log를 함께 검증해야 한다. 현재 예약 실행 증거 없음.

네이버/다음 검색 결과는 사진 재배포 허가를 뜻하지 않으므로 무차별 수집하지 않음. 실제 제공 API 자격증명·저장/재배포 조건을 확인한 경우 별도 공급자로 추가할 수 있음.
