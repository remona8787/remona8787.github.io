# v0.14.0 — 출시 준비 점검

2026-10-12. 코드·검증 측 준비 완료. 남은 출시 단계는 운영자 계정·결정이 필요하며 `release/launch/LAUNCH.md`에 순서대로 정리했다.

## 이번에 처음 실제로 실행한 검증
- **실제 브라우저 E2E** (Headless Chromium, 운영과 같은 `_headers` CSP 적용): 92개 통과, 1개 skip(Wikimedia 접근 불가 환경에서 사진 디코드). 모든 화면·정적 페이지를 360/1440px에서 런타임 오류·가로 넘침·터치 영역 기준으로 확인했고, axe-core WCAG 2.1 AA 검사, 방문 기록 유지·JSON 백업·테마·빈 검색·오프라인 셸·지도 로딩도 확인했다.
- **Supabase SQL을 실제 Postgres에서 실행** (PGlite, auth/storage 스텁): 부분 적용 상태 위 `complete-backend.sql`, 새 프로젝트 전체 순서, 재실행, 모든 public 테이블 RLS, 두 사용자 작업공간 격리·CAS 충돌, 방문 사진·Storage 소유자 제한, 편집 글 관리자 전용, 후보 승격 권한 차단. 정책을 일부러 약화하면 테스트가 실패하는 것도 확인했다.
- **Edge Functions**: Deno 2.5.4 타입 검사 0 오류. 로컬 실행 시 권한 함수 8개 모두 인증 없거나 틀린 비밀값 요청을 401로 거부.

## 고친 결함
- `404.html` 인라인 스크립트가 CSP에 막혀 동작하지 않았고, 상대 경로 리다이렉트는 깊은 경로에서 다시 404로 이어졌다. 정적 404 페이지로 교체.
- CSP `connect-src`에 `wss://*.supabase.co`가 없어 계정 연결 후 Realtime 동기화가 차단될 상태였다. 추가.
- Leaflet(unpkg)과 관리자 supabase-js(jsdelivr, 버전 미고정)를 CDN에서 불러오던 것을 npm 고정 버전 자체 호스팅으로 교체. CSP에서 외부 스크립트 출처 제거.
- `complete-backend.sql`과 archive/media 마이그레이션은 두 번째 실행에서 실패했다(정책 8개, 인덱스 2개). 재실행 가능하게 수정.
- 서비스워커가 config.js/app.js를 cache-first로 제공하는데 캐시 이름은 수동 변경이었다. 빌드 시 내용 해시로 자동 생성.
- 배포 문서·설정이 빌드 전 폴더를 가리켜, 그대로 올리면 로그인 번들이 빠졌다. `dist/` 기준으로 통일하고 vercel.json에 보안 헤더 추가.
- 모바일 8~10px 글자를 10~11px 이상으로, 독립 링크·요약·카드 버튼 터치 영역을 44px로 조정. 사이드바 링크 밑줄(색상만으로 구분되던 문제).
- Edge Function catch 블록 타입 오류 10건(동작 동일).
- CI 워크플로가 하위 폴더에 있어 실행되지 않았다. 저장소 루트로 옮기고 E2E·Deno 타입 검사 단계 추가.

## 추가한 것
- 개인정보 처리방침을 실제 동작 기준, 개인정보 보호법 항목 구조로 재작성. 이용 안내·지원·계정 삭제 페이지에 연락 경로 추가. 운영자/책임자/이메일은 `config.js`에서 채우며 비어 있으면 화면에 표시되고 `launch-check`가 차단한다.
- `scripts/deploy-edge-functions.sh`: 함수 8개 배포와 비밀값 생성·설정(터미널에 출력하지 않음).
- `scripts/serve.mjs`: `_headers`를 적용하는 로컬 정적 서버.

## 이 환경에서 확인하지 못한 것
- 네트워크 정책상 Supabase, 배포 주소, Wikimedia 접속 불가. 실제 서버 상태·사진 디코드·이메일 발송은 확인하지 않았다. PGlite 검증은 Supabase 자체 실행을 대신하지 않는다.
- 실기기(Android/iOS), 스토어 제출.
