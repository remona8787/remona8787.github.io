# v0.13.2 — SQL 작업 보류 중 가능한 보강

## 구현·검증 완료
- 개인 사진: 5MiB 입력 제한, JPEG/PNG/WebP 시그니처와 MIME 일치 확인, 디코딩 후 40MP 제한, 긴 변 2048px 이하 축소, 흰 배경 JPEG 재인코딩. 업로드 파일에서 원본 EXIF/GPS 메타데이터 제외. 변환 중 계정 전환 감지. 비공개 Storage 구조 유지.
- 사진 변환은 클라이언트 보호이며, 공격자가 직접 Storage API를 호출하는 경우까지 검증하는 서버 디코더는 아닙니다. 서버 업로드 검증/할당량 제한은 출시 전 추가 필요.
- 서버 이미지 다운로드: HTTPS upload.wikimedia.org 정확한 호스트만 허용, 리디렉션 거부, 30초 제한, 응답 스트림 15MiB 상한, MIME/시그니처 검사. 서버 코드 작성·문법 검사 완료, Edge 배포 미완료.
- 권리가 만료된 이미지의 기존 공개 Storage 객체 삭제 로직 추가. CDN/브라우저에 이미 캐시된 사본의 즉시 회수를 보장하지 않습니다.
- 출시 연결 점검 스크립트: npm run launch:check 또는 node scripts/launch-check.mjs release/launch/public-config.js. 읽기 전용이며 자동 회원가입/SQL 실행/사진 업로드를 하지 않습니다. 실패가 있으면 종료코드 1로 릴리스 준비 미완료를 표시합니다.
- Playwright 작성 시나리오에 360/390/412/430 모바일 너비 추가. 실행은 하지 않았습니다.

## 실제 네트워크 점검
release/launch/connectivity-report.json 기준:
1. 이메일 Auth 설정: HTTP200, enabled. 실제 가입/이메일 전달/로그인 검증 아님.
2. 공개 이미지 뷰: HTTP200. 이미지 데이터 존재 검사 실패(없음).
3. 장소+도시 관계 조회: HTTP400. SQL 적용 전 관계 미완성.
4. 관리자 글 테이블: HTTP404. SQL 적용 전 테이블 없음.
5개 항목 중 2개 통과, 3개 실패. 이 실패는 출시 준비 미완료를 탐지한 결과이며 테스트를 삭제하거나 성공으로 바꾸지 않았습니다.

## 보류 사항
사용자가 요청한 PC SQL 작업은 보류했고 Supabase 변경 요청을 추가로 하지 않았습니다. 이전의 complete-backend.sql과 적용 가이드를 그대로 보존했습니다. 현재 공개 앱의 백엔드 키는 계속 비어 있습니다. 잘못된 서버 연결을 활성화하지 않았습니다.
실제 사진 확보, 계정 두 개 RLS/동기화 테스트, 관리자 지정, 이메일 발송/redirect, 비공개 Storage 업로드, Edge 배포, Cron, 운영자 및 연락처, 실제 브라우저 E2E가 남아 있습니다. v1.0 런칭 완료 아님.
