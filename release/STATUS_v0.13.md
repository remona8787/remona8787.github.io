# 빛의 건축 v0.13 — 구현·검증 상태

2026-10-11 KST. v0.12 공통 웹 구조를 직접 확장했습니다. 신규 프레임워크로 재작성하지 않았고 기존 49개 장소, 저장·기록·코스·백업 기능을 유지했습니다. **Production-Ready / Store-Ready 판정 아님.**

## 이번 구현
- 홈: 브랜드 히어로/통합 검색/유형 선택/수록 우선순위 기반 추천/실제 데이터 지역/기존 큐레이션. 운영 확인 만료일까지 유효하고 공식 출처가 있는 콘텐츠만 ‘지금 볼 수 있는’ 영역에 노출. 해당 콘텐츠가 없으면 섹션을 숨김.
- 모바일 메뉴: 홈 / 발견 / 지도 / 저장 / 마이. 마이에 코스·일정·기록·계정·설정 통합.
- 검색: 장소명·영문명·국가·도시·건축가·작가·제작사 검색, 국가/도시/상태/콘텐츠유형/연도/정렬 필터. 없는 데이터의 필터 선택지는 비활성화. 일정상 진행과 실제 관람 가능 판정을 분리.
- 지도: 목록과 공통 검색 모델, 검증 상태+출처+유효 좌표 필수. 데스크톱 목록/지도 배치, 지도 이동 영역 목록 갱신, 마커 선택, 모바일 지도/목록 전환 및 드래그·키보드로 높이 조절.
- 상세: 전문 메타데이터 접기, 승인 미디어 갤러리/출처/저작권, 동일 유형 관련 프로젝트. 누락 필드는 미등록 표시.
- 저장: 국가·도시 그룹. 캘린더: 개인 코스 일정과 기간형 프로그램, 상설은 종료 행사에서 제외.
- 방문 기록: 다시 볼 장소 저장, 비공개 사진 업로드/조회/삭제 클라이언트. JPG/PNG/WebP 5MiB 이하. 실제 원본 사진·EXIF를 비공개 보관. 사진은 JSON 백업에 포함되지 않음.
- 관리자: 아카이브 글 초안/공개 등록 폼. 공개 승인된 글만 매거진 표시. 문구·사진·로고·데이터를 참고 사이트에서 복사하지 않음.
- 디자인: 이전 CSS를 정리해 녹색 규칙 제거. 밝은 본문 + 히어로 남색·보라 그라데이션, Coral 소량 강조, Noto Sans KR. 명암 모드 토큰 분리.

## 검증 증거
`release/VERIFICATION_v0.13.txt`: 기존 34 + 검색·데이터 노출 9 + 색 대비 8 = **51개**, 실패 0. DOM 테스트는 가짜 DOM 기반이며 실제 브라우저가 아닙니다. 색 대비 검사는 대표 전경/배경 토큰에 상대휘도 공식 `(밝은 휘도+0.05)/(어두운 휘도+0.05)`를 적용하여 4.5:1 이상을 확인하며, 전체 렌더링 화면 대비를 증명하지 않습니다.

`npm run build`, `npm run check`: 웹 빌드, 9개 JS 문법, 진입 자산, 관리자 복사본 일치, 모든 Edge Function TypeScript 문법 검사 통과. `npx cap sync`: Android/iOS에 v0.13 웹 코드와 플러그인 동기화 성공. APK/AAB/Archive 컴파일 성공을 뜻하지 않습니다.

`qa/ux.spec.mjs`: 실제 Playwright 시나리오 작성, **미실행**. 사진 0개면 사진 검사가 실패하도록 작성했습니다. Sites managed 지침에서 지정한 control-browser 스킬이 이 환경에 없어 임의 브라우저 실행을 하지 않았습니다. 화면 스크린샷·Lighthouse·실기기 E2E 증거 없음.

## 실제 Supabase 조회 결과
2026-10-11 연결 도구 호출 성공. `list_projects` 결과 `projects: []`. `list_organizations` 결과 조직 `JIHYUN-KIM` 한 개 확인. **새 프로젝트를 생성하거나 유료 리소스를 구매하지 않았습니다.** 생성 도구는 조직 선택과 비용 확인을 사용자에게 요구합니다. 따라서 DB·Auth·Realtime·Storage·Cron 실제 연결은 아직 안 됐습니다. 이전의 ‘도구 미노출’ 사유는 현재는 해소됐습니다.

## 데이터·이미지 미완료
- 사진 파일 다운로드는 Wikimedia에서 HTTP403. 승인된 실제 사진/썸네일 확보 및 브라우저 로딩 성공 미검증. 홈 대표사진은 확보되면 표시하는 조건부 코드이며 현재는 명시적 브랜드 영역입니다.
- 기존 49개 장소 좌표는 검증되지 않았으므로 지도 핀을 생성하지 않습니다. 전국·전세계 데이터 수집 완료 또는 실시간 수집 완료를 주장하지 않습니다.
- 24/48시간 수집 Cron은 실제 활성화·실행하지 않았습니다. ‘신규 업데이트’ 영역은 승인/갱신 데이터가 없으면 노출하지 않습니다.
- 날짜·제작자·기술 정보가 없으면 생성하지 않습니다. 지역은 기존 SEOUL 코드만 대한민국/서울로 분류하며, 해외 검색 후보는 검증 데이터와 구분합니다.

## 서버 확장 적용
CLI가 생성한 `supabase/migrations/20261010160920_archive_media_and_editorial.sql`은 기존 01..18 이후의 추가 SQL입니다. 아직 DB 실행·RLS Advisor·두 계정 권한 테스트를 하지 않았으므로 미검증입니다. CLI `db push`만으로 기존 숫자 SQL까지 적용되는 것은 아닙니다. docs/OPERATIONS_v0.12.md의 기존 SQL 적용 순서를 먼저 확인하세요.

Storage bucket visit-photos는 private, 최대 5MiB, MIME 제한. SELECT/INSERT/DELETE는 auth.uid 폴더만 허용하며 upsert/UPDATE는 사용하지 않습니다. visit_photos 메타데이터도 소유자 RLS. 개인 사진은 본인 UI에서 요청할 때만 60초 링크를 발급합니다. 발급된 링크를 가진 사람은 만료 전 접근할 수 있으므로 링크 공유 금지 안내가 필요합니다. 계정 삭제 함수는 사진 정리→세션 해제→계정 삭제 순서로 수정했습니다. 실패·재시도 및 잔존파일 검증은 실제 서버에서 필요합니다.
